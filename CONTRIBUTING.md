# Правила работы с репозиториями Pinkmine

## Ветки

| Ветка | Назначение | Как попадают изменения |
|---|---|---|
| `production` | Релизная версия. Из неё выполняется деплой на сервер | Только через PR из `development`, после зелёного CI |
| `development` | Тестовая версия, ветка по умолчанию | Только через PR из `feature/*` или `fix/*` |
| `feature/<issue>-<кратко>` | Новая функциональность по задаче из GitHub Projects | Создаётся от `development` |
| `fix/<issue>-<кратко>` | Исправление ошибки | Создаётся от `development` |

Прямые коммиты в `development` и `production` запрещены (branch protection).

## Задачи

Все задачи (issues) всех направлений ведутся в репозитории сервера `fpmi-hci-2026/hci-10-backend-api-group-9` и собраны в проекте GitHub Projects «Pinkmine». Направление задачи (Документация, API и бизнес-логика, Веб-приложение, Мобильное приложение) задаётся полем «Направление» проекта.

В репозитории сервера на задачу ссылаются коротко: `#<номер>`. В остальных репозиториях (основной, веб, мобильное приложение) — полным именем: `fpmi-hci-2026/hci-10-backend-api-group-9#<номер>`, иначе ссылка укажет на задачу этого репозитория.

## Порядок работы над задачей

1. Взять issue в колонке **To do** и перенести в **In progress**.
2. Создать ветку `feature/<номер issue>-<кратко>` от `development`.
3. Коммитить небольшими шагами. Сообщение коммита: `#<номер> что сделано` (в других репозиториях `fpmi-hci-2026/hci-10-backend-api-group-9#<номер> что сделано`).
4. Открыть PR в `development`, в описании написать `Closes #<номер>` (в других репозиториях `Closes fpmi-hci-2026/hci-10-backend-api-group-9#<номер>`), перенести задачу в **To check**.
5. CI (тесты, SonarQube, сборка Docker) должен быть зелёным. Другой участник команды проверяет PR и делает merge.
6. После merge задача переходит в **Done**.

## Релиз

Когда набор задач в `development` проверен, тимлид открывает PR `development → production`.
После merge CI повторно прогоняет тесты и проверку качества и запускает деплой на сервер.
